    一套不依赖 jQuery、面向 IE9+ 的原生 JS UI 框架。Core 负责加载、遮罩和 iframe 弹窗，组件负责界面，Util 提供工具函数，Third 负责 Excel 与图片导出适配。

    一、开始使用MelUi 是什么、产物怎么拿、页面怎么引

    1.1 整体结构

    MelUi 不是一个只有组件的 UI 包，而是四层结构：Core 提供运行时能力，组件负责界面，Util 提供工具函数，Third 把 Excel / 图片导出这类第三方能力包装成统一入口。

    LAYER 01
    Core 核心库

    Loading/Spinner、Mask、Iframe 等运行时能力，对外提供顶层 API。随主包一起加载，不存在单独的 melui.Core 对象。

    LAYER 02
    Components 组件

    Layout、Button、DatePicker、Dialog、Drawer、Pagination、Table 等 7+ 个 UI 组件；Loading 是 Core 能力。每个组件入口都有独立使用手册，复杂参数不堆在总入口里。

    LAYER 03
    Util 工具库

    主包内置基础函数；melui-util.js 再提供扩展模块与工具函数，按需引入。

    LAYER 04
    Third 第三方适配

    melui.third 提供 Excel 导出与网页导出图片两个适配 API。第三方库不内置，需业务页面自行引入。

    先记住一个边界：主包 melui.js 不打包 Util 扩展包。用到 melui.util.date、melui.util.format 这些扩展模块时，必须再引入 melui-util.js。

    1.2 产物与引入顺序

    产物 内容 什么时候需要
    melui.js / melui.min.js Core + 7+ 个 UI 组件，Loading 属于 Core 所有使用 MelUi 的页面，必引。
    melui.css / melui.min.css Core 与组件的整包样式 使用整包时，先于 JS 引入。
    melui-util.js / melui-util.min.js 扩展模块与工具函数 用到 melui.util.date、format、dom 等扩展模块时引入。
    melui-third.js / melui-third.min.js Excel 导出、网页导出图片 用 melui.third 时引入；还需自行引入 SheetJS / html2canvas。
    标准引入顺序
    <link rel="stylesheet" href="../release/dist/melui.min.css">
<script src="../release/dist/melui.min.js"></script>

<!-- 可选：工具库扩展 -->
<script src="../release/dist/melui-util.min.js"></script>

<!-- 可选：第三方适配 -->
<script src="../release/dist/melui-third.min.js"></script>

    CSS 必须先加载，再加载 JS；melui-util.js 和 melui-third.js 都排在主包之后。组件如果单独打包，则按组件目录下的独立 CSS / JS 引入，不要和整包混用。

    1.3 最小示例

    先确认 melui 已挂到全局，再调用 Core 的 Loading。下面的写法只依赖主包：

    JavaScript
    melui.showLoading('正在加载...');

setTimeout(function () {
    melui.closeLoading();
}, 1200);

    文档位置：本手册与各组件手册建议放在同一个 demo/ 目录。手册按钮全部使用相对路径，移动主文档时要同步调整。

    打开方式：直接双击 HTML 即可，不需要本地服务器。所有手册按钮都在新标签页打开，不使用 iframe 嵌套。

    二、兼容性与常见问题先看边界，再查问题；这部分放在最前面，避免后面反复解释

    2.1 浏览器与语法基线

    MelUi 的目标环境是 IE9+。框架源码使用 ES5 写法，不依赖 jQuery，不使用 let、const、箭头函数、模板字符串这类 IE9 不支持的语法。项目里的组件与工具函数都按这个基线维护。

    IE9 的两个实际限制：Loading 的转圈动画不支持 @keyframes，会显示静态四点环；部分 CSS 动画和滤镜效果会降级。遮罩、文字、滚动锁仍正常工作。

    2.2 命名与调用入口

    melui 与 MelUi 指向同一个命名空间，大小写都能用。Core 的顶层 API 全部提升到顶层，所以正确写法是 melui.showLoading()，不是 melui.Core.showLoading()。

    当前源码里不存在 melui.Core。旧架构文档里的 melui.Core 说法已经过时，不要照搬。Core 只导出白名单 API，内部实现不作为对外契约。

    类型 入口 说明
    Core melui.showLoading() 顶层 API 都不加 Core。
    工具库 melui.util.base.xxx / melui.util.date.xxx 基础函数随主包；扩展模块需 melui-util.js。
    组件 MelUi.Table(options) 组件使用大驼峰；Table 支持工厂写法，Pagination 可省略 new。
    第三方适配 melui.third.export2Excel() 需 melui-third.js，并自行加载 SheetJS / html2canvas。

    Layout 和 Button 是 CSS 类组件，入口不是构造函数：布局用 mel-row、mel-col、mel-span-N；按钮用 mel-btn 及修饰类。Dialog、Drawer、Table、Pagination、DatePicker 才走 JS 入口。

    2.3 引入顺序与依赖边界

    整包使用时，先 CSS、后 JS；工具扩展和第三方适配排在主包之后。第三方适配只负责调用，不内置 SheetJS / html2canvas，也不在运行时动态插 CDN。页面没加载对应库时，调用会给出提示，不会静默失败。

    主包边界：Core 与组件在主包；Util 扩展包单独；Third 单独。不要假设“引了 melui.js 就一定有全部 util 函数”。

    2.4 常见问题

    Q：页面提示 melui.showLoading is not a function？

    先确认 melui.min.js 已成功加载，且没有在 JS 执行前被其他脚本打断；再看是否只引了组件单包，却调用了 Core 的顶层 API。Core 随主包，不在组件单包里。

    Q：调用了 closeLoading()，Loading 还在？

    Loading 是计数式关闭：调用了几次 showLoading，就要对应调用几次 closeLoading。计数归零才会销毁或隐藏；多调 closeLoading 只会 warn，不会抛错。

    Q：isLoading() 返回 false，但页面上还有转圈？

    isLoading 只看全局 Loading 计数，不看 DOM。createSpinner 生成的局部转圈不计入这个计数，需要你自己保存实例并调用它的 destroy。

    Q：关闭遮罩时关错了层？

    closeMask() 不传参数关闭最后打开的一层；传 'all' 关闭全部；传 id 或节点关闭指定遮罩。遮罩支持多层叠放和滚动锁引用计数。

    Q：openIframe() 打开空白或直接失败？

    先看协议：当前页面是 HTTPS、目标地址是 HTTP 时，会被混合内容策略拦截，并给出提示。其次检查目标站点是否设置了 X-Frame-Options 或 CSP frame-ancestors，这类限制 MelUi 无法绕过。

    Q：melui.util.date 不存在？

    主包只有基础工具函数。date、format、dom 等扩展模块在 melui-util.js 里，需在主包之后额外引入。

    Q：melui.third 不存在，或导出 Excel 没反应？

    melui.third 需要单独引入 melui-third.js；Excel 导出还要求页面已加载 SheetJS，且浏览器为 IE11+。导出图片要求页面已加载 html2canvas。

    Q：执行 npm run build 末尾出现 npm update check failed？

    这是 npm 的更新检查器无法写入用户配置目录（Windows 下常见于 C:\Users\Administrator\.config）导致的提示，不是 MelUi 构建失败。以构建产物是否生成、构建命令是否返回成功为准；该提示不会影响 release/dist 的输出。

    三、Core 核心能力运行时底座；这里只做能力导航，参数和示例看对应手册

    Core 随主包加载，对外只暴露顶层 API，全部挂在 melui / MelUi 顶层；zIndex、scrollLock、polyfill 属于内部机制，不作为业务 API。

    CORE 能力
    Loading / Mask / Iframe
    统一由 melui 顶层 API 提供；不存在 melui.Core，不要写成 melui.Core.xxx()

    3.1 Core 负责什么

    Core 负责页面运行时最公共的三类能力：Loading 加载反馈、Mask 遮罩层、Iframe 内嵌弹窗。它不负责按钮、表格、日期选择器这类界面组件，也不包含 Util 工具函数或 Third 第三方适配。

    边界：组件可以复用 Core 的遮罩、层级和滚动锁，但 Core 不反向依赖任何组件；业务代码应调用 melui 顶层 API，不要访问内部模块。

    5.2 Third 第三方适配

    melui.third 是第三方适配层，当前提供 Excel 导出和网页导出图片两类适配 API。它只负责调用和统一提示，不内置第三方库，也不在 JS 里动态加载 CDN。

    API 作用 返回
    melui.third.export2Excel(options) 把表格导出为 Excel / CSV，使用 SheetJS 解析行列与合并单元格。 Boolean
    melui.third.exportWeb2Image(options) 把指定节点导出为图片；桌面端下载，移动端显示长按保存浮层。 Promise|null

    5.2.1 第三方依赖

    能力 需要页面自行引入 全局变量
    导出 Excel xlsx.full.min.js（SheetJS） XLSX
    网页导出图片 html2canvas.min.js html2canvas

    依赖边界：MelUi 不内置 SheetJS / html2canvas，也不会自动插 script 加载 CDN。业务页面要先引入对应库，再调用 melui.third。库没加载时，导出函数会给出提示并返回失败值。

    兼容提醒：Excel 导出在 IE9 / IE10 下会被明确拦截，要求 IE11+；图片导出以 html2canvas 自身兼容范围为准。

    官方资料：SheetJS（xlsx.full.min.js） / html2canvas。版本与下载路径按项目实际依赖为准。

    5.2.2 export2Excel 参数

    参数 默认 说明
    enabletrue是否启用导出；false 时提示并返回 false。
    filename'导出报表-'文件名前缀；空值会回退默认。
    fileAutoTimetrue是否自动追加时间戳。
    extension'.xls'支持 .xls、.xlsx、.csv。
    table'.mel-table'表格节点或选择器。
    exclude'.noExl'导出前从克隆表格中排除的节点选择器。

    实现上会克隆表格、剔除 exclude 命中的节点，再交给 SheetJS 的 table_to_sheet / writeFile。不依赖 Table 的导出插件，普通 HTML 表格也能用；但表格节点必须存在，且行列结构要能被 SheetJS 解析。

    5.2.3 exportWeb2Image 参数

    参数 默认 说明
    element'body'要导出的节点或选择器。
    filename'下载图片.png'文件名；不是 png / jpg / jpeg 时会自动补 .png。
    caption'长按图片“保存到手机”'移动端预览浮层的提示文案。
    closeCallBacknull移动端关闭浮层后的回调。

    桌面端调用会生成下载链接；移动端显示一张带提示和关闭按钮的浮层。节点不存在或 html2canvas 未加载时返回 null 并提示。导出函数在提示时都优先调用 melui.alert，没有 dialog 组件时退回原生 alert。
