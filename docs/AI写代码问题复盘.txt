MelUi Dialog 弹窗组件全维度复盘总结
逐条拆解目录、编码规范、迭代机制、IE 兼容、发布风险、行业规范对标，同时补齐遗漏隐患点
一、项目目录结构（固定标准，永久固化，杜绝路径反复出错）
1. 既定目录架构
plaintext
项目根目录
├─ src
│  └─ components
│     └─ dialog                # 弹窗组件独立文件夹
│        ├─ index.css          # 样式主文件（统一命名index.css）
│        └─ index.js           # 脚本主文件（统一命名index.js）
└─ demo
   └─ dialog-demo.html         # 本地演示页面
2. 标准引入路径（demo 内永久不变）
html
预览
<link rel="stylesheet" href="../src/components/dialog/index.css">
<script src="../src/components/dialog/index.js"></script>
3. 过往问题
前期随意更改根级存放、文件名混用 dialog.css/index.css，相对路径混乱，双击本地打开、网页服务器部署环境路径不统一。
4. 后续约束
组件必须收拢至 src/components/组件名 独立文件夹，入口固定 index.js / index.css；
demo 文件夹只存放调试示例，不存放源码；
如需新增多版本、主题变体，在 dialog 内部新建文件夹区分，不打乱顶层结构；
线上打包发布时，可直接打包 src/components/dialog 整目录。
二、代码书写规范（头部注释、行内注释、格式硬性准则）
（1）CSS 文件头部固定注释模板
css
/*
MelUi Dialog 弹窗组件样式
版本：v1.0.6
创建时间：2026-08-10
更新时间：2026-08-10
兼容：IE9 / IE10 / IE11、移动端自适应
说明：严格遵循既定布局与类名，禁止私自修改布局层级、z-index、flex规则
*/
（2）JS 文件头部固定注释模板
javascript
运行
/**
 * MelUi Dialog 弹窗对话框组件
 * 版本：v1.0.6
 * 创建时间：2026-08-10
 * 更新时间：2026-08-10
 * 兼容：IE9/10/11
 * 调用方式：
    构造实例：new MelUi.Dialog(options)
    快捷调用：MelUi.alert() / MelUi.confirm() / MelUi.prompt() / MelUi.dialog()
    小写兼容：melui.alert() 全局别名挂载
 * 交互硬性规则：
    alert：纯提示框，无输入框
    confirm：确认选择框，无输入框
    dialog：极简弹窗，无输入框
    prompt：唯一携带输入框的弹窗
 * 回调规则：
    onClick(ret)：ret从1开始计数；prompt额外携带输入文本参数
 */
（3）行内注释规范
默认配置 defaults：每项尾部统一 , // 说明文字，逗号后 1 个空格；
复杂逻辑分支（输入框渲染判断、按钮 class 拼接）必须单行注释说明意图；
IE 兼容处理代码单独注释标注；
无意义冗余注释全部删除，不堆砌废话。
（4）代码格式规范
缩进统一 2 空格；
变量命名小驼峰；常量可大写；
循环、函数首尾大括号同行；
禁止 ES6 语法糖（箭头函数、let/const 解构等），全程使用 ES5 语法适配 IE。
过往问题
头部注释缺失、版本时间随意篡改；
defaults 注释格式不统一；
擅自改写 CSS 布局、类名；
偶尔混入现代 JS 语法。
三、代码迭代更新机制（版本号、更新日志、更新规则）
1. 版本号规则（遵循语义化版本 SemVer，对标 ElementUI/Vant）
格式：主版本.次版本.补丁版本
v X . Y . Z
X（主版本）：架构重构、API 大规模改动、不兼容旧代码；
Y（次版本）：新增功能、新增参数、新增弹窗样式；向下完全兼容；
Z（补丁）：bug 修复、细节微调、兼容性优化；不新增功能。
示例：
v1.0.6 = 1 代架构，0 个新增大功能，6 次 bug 补丁修复
2. 更新同步规则
每次修改完成：
JS、CSS 头部 更新时间同步修改；
补丁修复：Z 数字 + 1；新增功能：Y+1，Z 归零；架构大改：X+1；
建立简易更新日志（建议在 dialog 文件夹新建 CHANGELOG.md）
记录：版本、日期、修改内容、影响范围、兼容性变化；
3. 迭代禁忌
绝不私自修改已有 API 参数名称、类名、回调入参；
修复 bug 只改动问题代码，不大范围重写整体逻辑；
新增功能默认关闭，通过参数开启，保证老项目无缝兼容；
过往问题
无版本管控，修改后时间、版本不更新，反复回退旧 bug 代码。
四、IE9/10/11 兼容性解决方案（现存问题 + 完整兜底方案）
现存原生隐患
IE11 flex 布局部分属性渲染偏差（gap 不识别）；
IE9 无 classList、querySelectorAll 兼容性小幅瑕疵；
IE 不支持 ES6 语法、箭头函数、let/const；
transform 居中在老旧 IE 渲染偏移；
分层兼容方案
语法层：全程强制 ES5
禁用：let/const、()=> 箭头函数、模板字符串、forEach 数组遍历；
统一使用：var、function、for 循环拼接字符串；
样式层兼容修正
flex gap 替换：用 padding+margin 模拟间距，规避 IE 不识别 gap；
transform 弹窗居中增加定位兜底；
圆角、阴影保留，IE 自动降级显示无圆角；
DOM 工具兼容补丁（可选，轻量引入）
如需极致稳定，引入极小 polyfill：
classList 兼容补丁；
数组 forEach 兼容；
仅在 IE 环境加载，现代浏览器不加载；
事件兼容
不用 addEventListener 特殊特性，点击事件统一原生绑定，杜绝事件冒泡差异；
边界底线
IE9 仅保证弹窗正常弹出、点击可用；圆角、细微视觉效果自动降级，不强行兼容全部视觉细节。
五、后期打包发布是否受影响（风险排查）
1. 正向有利点
纯 ES5 代码，无打包依赖、无框架耦合：
可直接原生引入使用，也可放入 webpack/rollup 打包；
目录收拢规范，打包时可单独导出 dialog 组件；
API 稳定向下兼容，存量项目升级仅替换 index.js+index.css 即可；
2. 潜在风险 & 规避
风险：随意修改类名、参数 → 线上页面样式错乱
规避：迭代严格遵循语义化版本，大版本才允许改动 API；
风险：IE 兼容补丁缺失导致老旧内网系统异常
规避：发布前必须在 IE11 完整自测一遍弹窗全部场景；
风险：demo 页面代码用于线上复制出错
规避：demo 仅作演示，线上业务自行重新编写调用代码；
风险：未做压缩，文件体积偏大
规避：发布产出压缩版 index.min.js/index.min.css，源码保留未压缩版本用于维护；
结论
规范维护前提下，完全不影响后期发布，适配内网传统系统、Web 管理后台、移动端网页多场景。
六、对标 ElementUI、VantUI 大厂插件规范契合度分析
相同点（符合行业通用规范）
组件收拢独立文件夹，入口 index 统一导出；
语义化版本迭代，更新日志留存；
区分基础调用 + 快捷语法（alert/confirm 全局快捷方式）；
配置参数集中默认 defaults，可全覆盖自定义；
弹窗层级 z-index 规范设计，避免层级覆盖冲突；
样式与脚本分离，可单独替换主题样式；
差距点（可小幅优化贴近大厂标准）
缺少 TS 类型声明文件（.d.ts），TS 项目无法获得代码提示；
没有 npm 包化、无法 npm install 引入；
缺少单元测试用例；
没有主题定制变量（颜色、圆角、尺寸统一 css 变量管控）；
没有弹窗拖拽、键盘 ESC 关闭、遮罩点击关闭等拓展配置；
折中优化方案（轻量化贴近大厂，不增加复杂度）
新增 CSS 全局变量管控主题色；
补充基础 TS 声明文件；
新增可选参数：esc 关闭、遮罩点击关闭、弹窗拖拽；
整体判定
基础架构、API 设计逻辑符合主流 UI 组件库设计思想，属于轻量化自研后台组件范式，适配国内政务、进销存、医疗评定这类传统后台场景；只是缺少工程化打包、TS、单元测试这类前端现代化配套。
七、额外遗漏隐患补充复盘
全局挂载污染隐患
当前挂载到 window.MelUi、window.melui，全局变量极少，无冲突风险；后续新增组件统一挂载 MelUi 命名空间，不散落全局变量；
弹窗实例销毁机制
关闭弹窗仅移除 DOM，无内存泄漏问题；连续频繁弹窗场景无需手动销毁，逻辑安全；
多弹窗层级堆叠
已固定 z-index 层级，先后弹出不会互相遮挡错乱；
移动端适配
当前已做 max-width、弹性适配手机屏幕，移动端打开不会溢出；
回调 this 指向
回调内部 this 未绑定，如需获取弹窗实例可预留参数，当前后台场景无刚需。
八、后续执行铁律汇总
目录、路径永久固定，绝不私自调整；
头部注释、版本、更新时间每次改动同步更新；
IE 兼容优先 ES5 原生语法，禁用现代 JS 特性；
循环绑定闭包、变量作用域问题写完必自查；
迭代遵循语义化版本，改动先确认兼容性。
