melui.core · melui.util · 架构决议稿

core 与 util 怎么分、怎么导、怎么打包

从 neatui 迁移到 MelUI 的一次彻底重构：源码按职责拆文件、内部保留分层、对外抹平层级。UI 能力与纯工具彻底解耦，工具库可以脱离框架单独使用。

框架 MellowUI（MelUi） 构建 Rollup · UMD · IE9+ 产物 melui.js + melui-util.js
01

定位与三条原则

先把最容易搅在一起的两件事分开：core 是 UI 底层运行时，util 是纯数据工具。边界不看"谁依赖谁"，而看"会不会产生 DOM、依赖界面样式"。

melui.Core

UI 内核

loading 转圈、遮罩、全局提示、滚动穿透、全局实例管理。会创建 DOM，依赖 melui.css，和界面强绑定。

melui.util

工具库

类型判断、对象合并、防抖节流、日期、金额、URL、文件。纯函数、无副作用、不碰 DOM，可脱离框架单独用。

MelUi.*

组件类

Table / Dialog / Drawer。大驼峰命名空间下的构造类，用 new 实例化，源码内部依赖 core 与 internal-util。

三条原则：① 源码内部分层，对外接口扁平；② 分层只服务框架维护，不强迫业务写 .Core；③ 代码只写一份，产物按需分开。

02

分层与依赖关系

对外只有一个根：全局单例 melui，高频 UI 方法直接挂顶层，完整内核留在 melui.Core 作高级后门；组件用大驼峰 MelUi.*。

03

源码目录结构

原则：一个文件一类职责。loading 全部逻辑在 loading.js，遮罩在 mask.js；index.js 只做胶水，不堆实现代码。后续加全局 message、confirm，直接新建文件再挂进 index。

src/
├─ index.js                框架主入口：组装 melui 单例、挂 MelUi 组件
├─ core/                   UI 内核
│  ├─ index.js             聚合层：导入各模块 + 定义 publicApi + 导出 Core
│  ├─ loading.js           showLoading / closeLoading
│  ├─ mask.js              openMask / closeMask
│  ├─ message.js           预留：全局轻提示
│  ├─ confirm.js           预留：全局确认框
│  └─ internal/            私有底层，仅 core 内部可 import
│     └─ buildMaskDom.js   构建遮罩 DOM 等底层方法
├─ components/             业务组件
│  ├─ table/
│  ├─ dialog/
│  └─ drawer/
└─ util/                   纯工具，禁止碰 DOM、禁止依赖 core
   ├─ internal-util/       基础共享工具（随主包）
   │  ├─ type.js           isObject / isArray / isString
   │  ├─ object.js         mergeObj / 浅拷贝 / 简单深拷贝
   │  ├─ func.js           debounce / throttle
   │  └─ index.js          聚合导出，供主包 import
   ├─ date.js              日期格式化、时间加减
   ├─ money.js             金额千分位、保留小数
   ├─ string.js            脱敏、uuid、字符串处理
   ├─ url.js               参数解析、query 拼接
   ├─ file.js              blob、下载、base64
   └─ index.js             工具包入口，产出 melui-util.js

为什么不用一个大文件

  • 一个 js 塞几百上千行，后续加 message、confirm 会膨胀成灾难，就是"又臭又长"。
  • 拆文件后 git 改动范围小，冲突少；改 loading 动画不碰 mask 代码。
  • internal 与 public 一眼可分：放在 internal/ 下的就是私有实现，随时可重构。
04

依赖硬约束

这套目录能长期不烂，靠的是几条单向依赖。违反其中任何一条，后面必然出现循环引用或产物污染。

模块允许依赖禁止依赖说明
corecore/internal、util/internal-utilcomponents、util 业务工具可 取基础工具，不可 反向拉业务工具进主包
componentsmelui.Core、util/internal-utilcore/internal组件只调公开 UI 能力与基础工具
util/*仅原生 JScore、components、DOM纯函数，保证可独立复用
core/internal无被 core 以外任何模块 import私有实现，改名不算破坏性变更

最容易犯的错：core 为了省事写 import '../util/index.js'（引工具包入口），打包时会把 date、file 全部拖进主包，拆包等于白做。core 只能引 util/internal-util/xxx.js 的具体文件。

05

导出设计

所有能力在各自文件里 export，由入口聚合。核心是 publicApi 白名单：只有登记过的 API 才会提升到 melui 顶层，私有方法留在 melui.Core 里。

loading.js / mask.js：实现写在文件里

// src/core/loading.js
import { internalBuildMaskDom } from './internal/buildMaskDom.js';

export function showLoading(options) {
  internalBuildMaskDom();   // 完整实现：建 DOM、锁滚动、记实例
}
export function closeLoading() {
  // 移除节点、清状态
}

core/index.js：只做聚合，不写实现

// src/core/index.js
// 导入各个功能实现文件
import { showLoading, closeLoading } from './loading.js';
import { openMask, closeMask } from './mask.js';
import { internalBuildMaskDom } from './internal/buildMaskDom.js';

// 对外白名单：会提升到 melui.xxx
export const publicApi = { showLoading, closeLoading, openMask, closeMask };
// default导出完整内核：公开 API + 私有底层，挂载到 melui.Core
export default { ...publicApi, internalBuildMaskDom };

新增一个全局 UI 能力，只需新建文件、在 index 里 import、往 publicApi 加一行，已有文件完全不动。

util 基础工具：单文件单职责

// src/util/internal-util/object.js
  // 每个文件单独 export 函数，示例 object.js
export function mergeObj(target, ...sources) { /* 合并实现 */ }
export function isObject(val) { /* 判断实现 */ }

util/index.js：工具包入口，产出 melui-util.js

// src/util/index.js
import * as type from './internal-util/type.js';
import * as object from './internal-util/object.js';
import * as func from './internal-util/func.js';
import * as date from './date.js';
import * as money from './money.js';
import * as string from './string.js';
import * as url from './url.js';
import * as file from './file.js';

// 全部工具集合
const utilAll = { ...type, ...object, ...func, ...date, ...money, ...string, ...url, ...file };

// UMD全局挂载逻辑：追加到已有 melui.util，绝不覆盖主包内置的基础工具
if (typeof window !== 'undefined') {
  window.melui = window.melui || {};
  window.melui.util = Object.assign(window.melui.util || {}, utilAll);
}

export default utilAll;

src/index.js：框架主入口

// src/index.js
import Core, { publicApi } from './core/index.js';
import Table from './components/table/index.js';
import Dialog from './components/dialog/index.js';
import * as UtilBase from './util/internal-util/index.js';

const melui = {
  Core,        // 完整内核，高级入口
  ...publicApi // 等价于逐行 melui.showLoading = Core.showLoading，但不用手写
};

melui.util = UtilBase;         // 主包内置基础工具

window.MelUi = { Table, Dialog }; // 组件构造类，大驼峰
window.melui = melui;            // 全局单例，小写

为什么用 ...publicApi 而不是手写一堆赋值：函数仍是同一个引用（不是复制），Core 内部改了实现，顶层 melui 自动同步。新增顶层 API 不用回入口改代码，也避免 Object.assign(melui, Core) 那种把私有方法全部泄露的写法。

06

打包与产物

两个独立入口，两套产物。主包负责 UI 与组件，扩展包负责完整的工具能力，互不牵连。

// rollup 双入口（示意）
export default [
  {   // 主包
      input: 'src/index.js',
      output: [
        { file: 'dist/melui.js',      format: 'umd', name: 'melui' },
        { file: 'dist/melui.min.js',  format: 'umd', name: 'melui', plugins: [terser()] }
      ]
  },
  {   // 工具扩展包
      input: 'src/util/index.js',
      output: [
        { file: 'dist/melui-util.js',     format: 'umd', name: 'meluiUtil' },
        { file: 'dist/melui-util.min.js', format: 'umd', name: 'meluiUtil', plugins: [terser()] }
      ]
  }
];
产物内容说明
melui.js
melui.min.js		core 内核 + 全部组件 + internal-util 中被引用的函数Tree-shaking 只带走 import 到的函数，date/money/file 视为死代码剔除
melui.css
melui.min.css		框架样式core 的 loading / 遮罩依赖它，不能脱离
melui-util.js
melui-util.min.js		internal-util 全部 + date / money / string / url / file可单独用于非 MelUI 项目；加载后向 melui.util 追加方法

源码是多个小模块，产物是单个文件。使用者感知不到源码的拆分，只认 melui.xxx 调用。

07

使用方式

只引主包：只需 UI 能力

<link rel="stylesheet" href="melui.css">
<script src="melui.js"></script>

<script>
  melui.showLoading();          // 顶层扁平，不用写 .Core
  melui.closeLoading();
  melui.openMask();

  // 内置基础工具
  var opts = melui.util.mergeObj({ a: 1 }, { b: 2 });
  // 组件实例化
  var table = new MelUi.Table('#demo', {});   // 组件用 new
  // 高级底层内核API（普通业务不推荐，仅深度定制）
  melui.Core.internalBuildMaskDom();          // 底层后门，业务不推荐
</script>

主包 + 工具扩展包：需要日期、金额等

<link rel="stylesheet" href="melui.css">
<script src="melui.js"></script>
<script src="melui-util.js"></script>

<script>
  melui.showLoading();

  // 扩展包加载后，这些方法自动出现在 melui.util 上
  var d = melui.util.formatDate(new Date(), 'yyyy-MM-dd');
  var p = melui.util.formatMoney(1234.56);
</script>

引入顺序：css → melui.js → melui-util.js。扩展包内部用 Object.assign 追加，不会覆盖主包已有的基础工具。

08

对外暴露规则

大厂的做法可以概括成一句：源码内部分 core，业务侧看不到 core。Element Plus、Ant Design、axios 都是把内核高频能力代理到顶层命名空间，内核对象本身只留给深度定制。

入口调用示例放什么业务常用
melui 顶层melui.showLoading()
melui.openMask()		publicApi 白名单里的高频 UI 方法是
melui.utilmelui.util.mergeObj()全部纯工具函数，自成一组是
melui.Coremelui.Core.internalXxx()完整内核：公开 + 私有底层否，深度定制
MelUi.*new MelUi.Table()组件构造类是

工具不全部扁平到 melui. 根上：工具会持续增加，堆在根上迟早和 UI 方法撞名，比如以后 core 加 melui.download()、util 也加 download，就是隐性覆盖。放在 .util 下天然分组，文档也好归类。

09

维护流程

新增一个全局 UI 能力（如 message）

  1. 新建 src/core/message.js，写完整实现并 export。
  2. src/core/index.js 里 import 这些函数。
  3. 在 publicApi 对象中登记，决定是否提到 melui 顶层。
  4. 打包后即可 melui.message()；不登记的留在 melui.Core。

新增一个工具函数

  1. 组件或内核会用到的基础工具 → 放 util/internal-util/，自动进主包，代码只有一份。
  2. 业务侧才用的格式化、下载类工具 → 新建 util/xxx.js，在 util/index.js import 并合并，随扩展包输出。
  3. 不再需要的旧函数在重构期直接删，不做兼容层。
10

命名规范与风险清单

命名约定

  • 函数：小驼峰，动词开头，语义直白 —— showLoading、closeLoading、mergeObj、formatDate。
  • 全局单例：小写 melui（对应 axios、dayjs 这类单例对象）。
  • 组件构造类：大驼峰 MelUi.Table，用 new。
  • 工具命名空间：小写 melui.util；内核命名空间：melui.Core（大写 C 作为底层标记）。
  • 私有内部函数：internalXxx 前缀，只出现在 core/internal/。

风险清单

  • ✕ 直接 Object.assign(melui, Core)：私有方法全泄露，后续改名即破坏性变更。
  • ✕ core 引入 util/index.js：整包工具被打进主包，拆包失效。
  • ✕ 组件 import core/internal/：私有实现一旦重构，组件跟着崩。
  • ✕ melui-util.js 直接赋值 melui.util = utilAll：覆盖主包基础工具，mergeObj 直接消失。
  • ✕ 同一个工具在 core 与 util 各写一份：改 bug 要改两处，迟早不一致。
